# Troubleshooting (symptoms actually hit while building and verifying this repo)

| Symptom | Cause | Fix |
| --- | --- | --- |
| `experiment ... is invalid: - unknown key algorithm.lrr` | typo in the YAML | `strl plan` lists every problem at once; fix and re-plan |
| `reward component 'pass_all_test' ...` / `does not accept parameter(s)` | wrong component name / param | names come from `strl/tasks/<env>/rewards.py`, `strl/rewards.py` COMMON, or `module:function` |
| a custom GSM8K reward has no effect | row `env_class` overrode the env (SkyRL dataset.py:89) | fixed in `strl.entrypoint.prepare_dataset`; check `environment.env_class=strl_env` in `artifacts/schema.json` (in the pod; synced to `s3://.../attempts/<attempt>/artifacts/schema.json`) |
| `N <split> prompts exceed algorithm.max_prompt_tokens` | SkyRL would silently drop them | raise `max_prompt_tokens` (train/validation only; test prompts are never filtered) |
| `train dataset has N rows after SkyRL prompt-length filtering, expected M` | prompts dropped by SkyRL | same as above; re-run `strl prepare` |
| `reference fails: wrong_answer` for tasks returning `Counter` | harness rejected a stdlib `__eq__` | fixed: only candidate-defined `__eq__` is rejected; `strl prepare` would flag a regression |
| `deployed executor version X != local harness Y` | rolling deploy, old warm container answered | `strl executor deploy` (recreate strategy + polling); results carry `harness_version` |
| `environment/infra_error` > 0 / `masked_group_fraction` > 0 | Modal transport/timeouts | groups are masked (no bias); > 5% means the executor is overloaded: raise `max_containers` or lower `max_env_workers` |
| `executor infrastructure error during validation` | in-loop eval refuses biased metrics | retry the attempt; check Modal status / `strl executor check` |
| `RuntimeError: Canary requires a real nonzero finite policy gradient` | all groups had equal rewards in 2 steps | expected only on tiny/hard setups; `coding_harbor` disables the check (all-zero is legitimate for small agents) |
| `stage`: `FileNotFoundError ... evidence/<attempt>/job.json` | old CLI | fixed (directories are created) |
| `attempt X was already staged against a different budget ledger` | write-once attempt ledger copy | choose a new attempt name |
| `Insufficient remaining budget` | program ledger exhausted for this preset | record terminal attempts (`strl ledger`), use a smaller slice, or ask for budget |
| job `FAILED` with no `budget.json` / `worker-started.json` in S3 (a large-model dry run on 2 CPU pods) | the in-pod bootstrap died while downloading the 55.6 GB weights: 16 files x 16 parts filled the 30 GiB pod's memory (page cache) and stalled; a dry run never needs weights | fixed: 4 files x 8 parts, and `--mode dry` skips `*.safetensors`. Diagnose with a one-pod CPU job that writes status to S3 (the API exposes no logs): sequential download 390 s, the old 16 x 16 pattern 683 s |
| 2 x 8 job `QUEUED` with `status_detail: waiting_for_network_domain_capacity` for hours | topology: 2 ready nodes in one network domain | `strl launch` already races all four routes; add `--max-wait-hours H --fallback-set compute.nodes=1` if a 1-node result is acceptable (ask the user), and keep CPU work going meanwhile |
| held-out eval silently drops the tasks the policy failed | agent timeout / output-length overflow masked as infra | fixed: those score 0 in evaluation (never retried; an agent timeout whose verifier never started is `verifier_missing`, an infrastructure mask); training masks them as `agent_timeout` (no tokens exist). Watch `environment/<domain>/masked_group_fraction` and `eval/<domain>/no_artifact_rate` |
| every `terminal_bench` general trial masked as `infra_error` / the image cannot be built | exporter gave them the MCP-sidecar Dockerfile (`COPY general_env/...`) and their tests write only `reward.txt` | fixed: plain Dockerfile with `CMD sleep infinity`; the shared entrypoint accepts them as having run only with pytest's `ctrf.json` or the anti-hack guard's REJECT |
| `capacity`: `not enough distinct ready nodes in one network domain` with large headroom | cluster busy right now | launch anyway (the race queues on every route) or a smaller slice; don't chase fluctuations |
| `scaletrain.py submit` TypeError after POST | old helper (datetime in receipt) | fixed (`default=str`); `strl submit` reconciles by name if anything goes wrong |
| `NoCredentialsError` from LiteLLM key resolution on the laptop | no ambient credentials to assume `ml-worker` | run LiteLLM work in a pod: a dry run with `--set run.ceiling_per_domain=2` (see credentials.md); do not export admin credentials yourself |
| `aws s3 cp ... AccessDenied` on `scale-ml` | wrong profile | `production-developer` |
| `No module named 'vllm_router'` in the trainer | the image skips it | `strl/runtime.ensure_router` loads `assets/runtime/vllm_router-0.1.14.post1-...whl` (`strl fetch` downloads it) |
| `No module named 'dockerfile_parse'` / `harbor` in the pod | overlay missing | `strl overlay`; `stage` refuses Modal experiments without it |
| Harbor `Unknown parameter: 'session_id'` / `max_tokens is not supported` (external models) | OpenAI-family proxy routes | `strl eval-llm` drops `session_id` and uses `max_completion_tokens` |
| `SyntaxWarning: invalid escape sequence` during `prepare` | MBPP references | silenced; harmless |
| zsh: `set -- $spec` does not split / `==` not found | zsh word-splitting | use bash or Python loops for batch staging |
| `strl monitor` shows `BUDGET` and `node_h` > 1 at step 1 of a 4-GPU attempt | metric bug in attempts staged before 2026-10-06 13:00 (`ab-*-a1`): the program's unused budget was added | fixed: `budget/consumed_node_hours` = nodes x GPU fraction x worker wall-clock. The deadline was always correct; the ledger (`strl ledger`) is the budget source of truth |
| custom `module:function` reward passes locally but `No module named ...` in the pod | module outside the shipped tree | put it in `user_rewards/`; `strl plan` now rejects modules outside the repo and `stage` ships the package |
| Harbor canary/run: reward 0 everywhere, `generate/num_error_trajectories` = batch size, `harbor-trials/*/exception.txt` says `ContextLengthExceededError` | context smaller than Terminus-2's first turn (0.8–2.5k tokens) | `environment.harbor.max_seq_len` (default 8192) sizes the engine, the agent and the trainer together; plan rejects values that cannot fit turn 1; the canary now fails on >= 50% masked groups |
| Harbor W&B eval keys like `eval/_workspace_strl-run_..._mbpp-train-0601/pass_at_1` | upstream `HarborTaskDataset` labels data_source with the task path | fixed: labelled by benchmark (`eval/mbpp/*`, `eval/humaneval/*`) |
| `Missing successful real training canary (No training progress for 603s (stall_seconds=600))` on Harbor | the watchdog limit was below a healthy agentic step plus eval | Harbor base sets `stall_seconds: 1800`, `canary_max_seconds: 2400`; progress is now written at every optimizer step; plan rejects `stall_seconds` < 2 x `environment.harbor.agent_timeout_sec` + 300 (1,500 at the default 600) |
| a CPU (`--mode dry`) job on `gen_ai.agents_research` never leaves `QUEUED` | that team has no CPU quota for the preset | the race wins on `fb`; for a single submit use `--routes fb` |
| job `QUEUED` with `status_detail: preemption_reported` after it was running | borrowed capacity reclaimed | `strl launch --watch --relaunch-on-preempt 2` relaunches (and resumes with `evaluation.durable_checkpoints: true`); otherwise `strl ledger` it and launch a new attempt |
| `strl plan`: `model.profile='qwen3_5' is for [...] but <model> is [...]` | a base YAML or `--set model.profile` forced a profile for another family | delete `model.profile` (auto-detect) |
| `strl plan`: `<model> is a vision-language wrapper (...ForConditionalGeneration) with no registered profile` | VLM checkpoints need a profile that loads the language model only | pick the text-only checkpoint, or add a profile (extending.md) |
| `strl plan`: `cannot read config.json for <model>@<rev>: offline, a wrong revision, or a GATED model` | no network, a typo in `model.revision`, or a gated HF repo (Llama, Gemma) | accept the license on HF with the account whose token `strl fetch` uses, or choose an ungated model |
| `stage`: `<dir> holds <other model>@<rev>, not <model>@<rev>` | `model.local_path` points at another model's weights | leave `model.local_path` unset (default `assets/models/<name>@<rev12>`, with a `strl-model.json` identity marker) and `strl fetch` |
| `stage`: `run.resume_from=<a>: no durable checkpoint in S3` / `a checkpoint resumes only at the same world size` | the previous attempt saved no durable checkpoint, or the GPU count changed | resume only attempts run with `evaluation.durable_checkpoints: true`, on the same `compute.nodes` x `gpus_per_node` |
| W&B run shows no final `test/*` but S3 has `result.json` | W&B was unreachable at the end | `completion.json` records `wandb_error`; S3 is the source of truth; `strl verify` / `strl report` re-push |
| policy init: `ImportError: cannot import name 'LossKwargs' from 'transformers.utils'` (Phi-4-mini, `modeling_phi3.py` in the HF modules cache) | SkyRL loads with `trust_remote_code=True`, and `config.json`'s `auto_map` points at the repo's bundled modeling file, written for an older transformers | fixed: the worker drops `auto_map` when transformers has the architecture natively (`model_code` in `worker-started.json` / `dry-run.json`: `remote_code_dropped`); a model whose class cannot import fails the free dry run |
| `Fail-fast (domain_masked): 88% of music GRPO groups were masked` with `no_rollout (exception OutputLengthExceededError)` warnings | a small policy's single-shot reply overflowed `max_generate_length`; Harbor returns no tokens and it was counted as an infrastructure mask | fixed: an overflow is a scored placeholder (reward 0, zero loss), counted in `generate/<d>/num_output_exceeded` and `dropped_group_fraction`, never in `masked`. If a domain has no trainable groups, raise `algorithm.max_generate_length` |
| `strl launch`: `attempt name ... is too long: with these flags the launcher may create ...` | `--fallback-set` adds `-alt`, `--relaunch-on-preempt N` adds `-p<N>`, the race adds `-fb`... | shorten the attempt name (the message gives the maximum) |
| `strl plan`: `DATA: ... is not prepared for this selection` / `LEDGER: ... does not exist` | `run.data_dir` lacks the configured tasks; the ledger file is missing | `strl prepare <exp>`; a ledger only with the user's GPU-budget authorization |
| `strl plan` on a big model: `MEMORY: vLLM weights ... leave no KV room` | bf16 weights / TP exceed `gpu_memory_utilization` x 80 GB | raise `inference.tensor_parallel_size` (engines = GPUs / TP); the offline final eval follows the same TP |
| a staged CPU job (`strl stage-model`) seems to vanish | it is a plain submit, not a race | `strl status <job_id>` until COMPLETED, then `aws s3 ls .../models/<name>@<rev12>/` shows the files and `strl-model-manifest.json` |
| `stage`: `model not staged locally ... nor in S3` for a dry run | even a dry run needs the manifest (the pod skips only the weights) | `strl fetch` (small) or `strl stage-model` (large) first |
